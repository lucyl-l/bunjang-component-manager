# bunjang-component-manager

번개장터 디자인 시스템의 컴포넌트 진행 현황 관리 도구입니다.

**서비스 주소** · https://lucyl-l.github.io/bunjang-component-manager/
**관리 주체** · 디자인팀 (플랫폼 스쿼드 PD)

## 개요

디자인 시스템의 규모가 확대됨에 따라 컴포넌트 수가 증가하며,
각 컴포넌트의 **디자인 / iOS / Android / Web** 별 진행 단계를
개별적으로 추적·관리하는 데 어려움이 발생합니다.

본 도구는 전체 컴포넌트의 진행 현황을 단일 화면에 통합하여,
진행 상태의 **파악 · 갱신 · 이력 관리**를 효율화하는 것을 목적으로 합니다.

## 주요 기능

- 컴포넌트별 **디자인 · iOS · Android · Web 진행 상태** 추적
- 시트 및 상세 화면에서의 **상태 · 우선순위 즉시 변경** (자동 저장)
- 행 **드래그를 통한 순서 변경**
- 컴포넌트별 **토큰 · Props 관리**
- 모든 변경 사항에 대한 **자동 저장 및 이력 기록**

## 사용 안내

### 컴포넌트 등록

1. 우측 상단 **[컴포넌트 추가]** 선택
2. 이름, 우선순위, 플랫폼별 상태, 토큰, Props 입력
3. **[추가]** 선택 시 시트에 등록

### 진행 상태 관리

- 시트의 상태 항목을 선택하여 즉시 변경 (자동 저장)
- 컴포넌트 선택 시 상세 화면에서 우선순위 · 토큰 · Props 확인 및 수정
- 행 드래그를 통한 순서 변경
- 모든 변경 사항은 자동 저장되며, 변경 이력이 기록됨

### 토큰 일괄 등록 (JSON)

토큰은 개별 입력 외에 **JSON 파일을 통한 일괄 등록**을 지원합니다.

1. 컴포넌트 상세 화면에서 **[수정]** 모드 진입
2. 토큰 영역의 **[json 파일로 불러오기]** 선택
3. JSON 파일 선택 시 해당 컴포넌트의 토큰이 일괄 등록

> 일괄 등록 시 **기존 토큰은 전체 삭제 후 신규 파일 내용으로 대체**됩니다.
> 지원 형식: 평면 배열 `[{cat, name, desc}]` 또는 DTCG 중첩(`$value` / `$type`) 형식

## 로컬 실행

별도 빌드 과정 없이 정적 파일로 동작합니다.

```bash
# 저장소 클론
git clone https://github.com/lucyl-l/bunjang-component-manager.git

# 디렉터리 이동 후 로컬 서버 실행 (예시)
cd bunjang-component-manager
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000` 접속

> `index.html`을 직접 열 경우, API 키의 도메인 제한으로 데이터 연결이 제한될 수 있습니다.
> 로컬 테스트 시에는 위 방식(로컬 서버) 사용을 권장합니다.

## 데이터 구조

Firestore `components` 컬렉션에 컴포넌트 단위로 저장됩니다.

| 필드 | 타입 | 설명 |
|------|------|------|
| `id` | number | 컴포넌트 고유 번호 |
| `order` | number | 시트 노출 순서 |
| `name` | string | 컴포넌트명 |
| `priority` | string | 우선순위 (상 / 중 / 하 / 완료) |
| `status` | object | 플랫폼별 진행 상태 `{design, ios, android, web}` |
| `tokens` | array | 사용 토큰 `[{cat, name, desc, isSemantic}]` |
| `props` | object | Props 정의 `{속성명: [옵션...]}` |
| `updates` | array | 변경 이력 (최신순) |

### 진행 단계 정의

- **디자인**: 시작 전 → 구조 설계 중 → 컴포넌트 제작 중 → 컴포넌트 수정 중 → 크로스체크 진행 중 → 컴포넌트 제작 완료
- **개발**: 시작 전 → MCP 연동 중 → MCP 연동 완료 → 크로스체크 진행 중 → 코드리뷰 중 → 완료

## 코드 구조 및 유지보수

| 파일 | 역할 |
|------|------|
| `index.html` | 화면 구조 |
| `style.css`  | 스타일 (색상 · 여백 · 타이포그래피) |
| `script.js`  | 동작 및 기능 |

- 디자인 수정: `style.css`
- 기능 수정: `script.js`
- 수정 후 커밋 시, 약 1~2분 내 서비스에 자동 반영됩니다.
